# Crud

`crud <quid>` prints a doc: from the bridge's kb, then the kbs of the repos checked out in its workspace, then the docs of the capes that are loaded, so a cape's own action docs can be read anywhere. The edits below find their doc the same way, and commit in the repo it lives in.

`crud <kind> <gist>...` mints a doc of that kind in the bridge's kb, and `crud <repo>:<kind> <gist>...` in the kb of that repo's checkout in the workspace, which must be there. It commits in the repo it wrote to. Its name is `--name`, or the gist's first words slugged with the id's last six characters, and its meta is whatever `--meta <source>` reads, so a kind with required meta, such as a repo's `remotes`, can be minted.

The `--meta`, `--scopes` and `--links` usages read a YAML or JSON mapping from `<source>` (`-` for stdin) and merge it into that field, then commit:

- `--meta`: a JSON merge patch onto `meta`.
- `--scopes` and `--links`: keyed by repo or link target; each value is merged onto that entry, a new key is appended, and `null` removes the entry.

Whatever a doc's kind is, crud checks its `meta` against that kind's schema when it mints the doc or changes its meta: the kind comes from the kb being written, then the bridge's, then the loaded capes. A kind nothing declares is written with a warning, unchecked.
