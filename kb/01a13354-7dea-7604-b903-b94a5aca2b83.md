# Crud

`crud <quid>` prints a doc: from the bridge's kb, then the kbs of the repos checked out in its workspace, then the docs of the capes that are loaded, so a cape's own action docs can be read anywhere. The edits below find their doc the same way, and commit in the repo it lives in. They refuse a doc git does not track, such as a tool's local copy, before writing anything, since its change could never be committed.

`crud <kind> <gist>...` mints a doc of that kind in the bridge's kb, and `crud <repo>:<kind> <gist>...` in the kb of that repo's checkout in the workspace, which must be there, in a base. It commits in the repo it wrote to. Its name is `--name`, or the gist's first words slugged with the id's last six characters, and its meta is whatever `--meta <source>` reads, so a kind with required meta can be minted.

`crud repo <gist>... --name <name>` mints a repo the bridge owns, so it also creates the repo's home copy, `<home>/<uuidv5(name, root)>.git`, `home` being a path in the bridge's config. The copy mirrors the repo's first remote, or is an empty bare repo when it has none. Without `--name`, or a `home`, or when the home cannot be reached, it refuses and nothing is minted. `crud <repo>:repo` registers a repo in a workspace kb, with no home copy.

The `--meta`, `--scopes` and `--links` usages read a YAML or JSON mapping from `<source>` (`-` for stdin) and merge it into that field, then commit:

- `--meta`: a JSON merge patch onto `meta`.
- `--scopes` and `--links`: keyed by repo or link target; each value is merged onto that entry, a new key is appended, and `null` removes the entry. An entry the patch does not name keeps its written form, and one left with no fields is written as `{}`.

`--parent <parent>` makes `<parent>` the doc's only `parent.feat`: its other `parent.feat` links go, with those parents' `child.feat` links back to it, and `<parent>` gains a `child.feat` link to it, all in one commit. Both docs must be in the same kb, and a parent that is the doc itself or under it is refused.

Whatever a doc's kind is, crud checks its `meta` against that kind's schema when it mints the doc, changes its meta, or changes its kind (`--kind <kind>`): the kind comes from the kb being written, then the bridge's, then the loaded capes. A kind nothing declares is written with a warning, unchecked.

`--gist <gist>` and `--name <name>` replace those fields; quote a gist of more than one word.

A doc's body is its title, the one `# ` heading that starts it, then everything under it, and crud keeps the title apart so no edit loses it:

- `--title <title>` sets the title, adding one when the doc has none.
- `--body <source>` replaces everything under the title with the text `<source>` holds (`-` for stdin, else a file), as text, not YAML. An empty source leaves only the title.
- `--section <heading> <source>` replaces the `## <heading>` section, up to the next `## `, with that text, or appends it when the doc has no such section; an empty source removes it.
- `--replace <old> <new>` replaces the one place the text `<old>` holds occurs under the title with the text `<new>` holds. Both are sources (`-` for stdin, at most one of them), each losing one trailing newline; it refuses text found nowhere or more than once. They are sources rather than arguments because on Windows the global command is a `.cmd` shim, which cuts an argument at its first newline and mangles quotes; a file keeps every newline and backslash.

`--body`, `--section` and `--replace` refuse a doc with no title, saying to set one first, rather than guessing where its body starts.

`crud --batch <source>` applies a YAML list of edits in order and commits once per repo. Each item names a doc by `quid` and one edit keyed as its flag: `title`, `body`, `gist`, `name`, `kind`, `meta`, `scopes`, `links` and `parent` take the flag's value, `section` takes `{heading, text}` and `replace` takes `{old, new}`. Text is inline, so a block scalar carries any newline or backslash without a file. Each edit refuses as its flag would, naming its item, and then nothing is written. The commit is the single edit's message for one doc, else `crud: updated N docs`.

`crud --drop <quid>` deletes a doc's file and commits, and never edits another doc. While any doc in the bridge or a workspace kb links to it (its parent's `child.feat` and its children's `parent.feat` included), or mentions its id in its body, or a config names it as its root, it refuses, naming each; move or remove those first with `--links`. A doc whose kind is durable (`meta.durable: true` on its kind doc) is refused even then, since its file is what keeps it findable to anyone holding its id; `--hard` deletes it anyway.

`crud --drop-list <source>` drops every doc whose quid `<source>` lists, one per line (`-` for stdin), together in one commit per repo. Only links and mentions from docs outside the list count, and from docs git tracks (a doc git ignores, such as a tool's local copy, is no part of the kb's history), so a set of docs that all mention each other, which no single `--drop` could ever start on, goes at once. `--hard` works as for `--drop`.
