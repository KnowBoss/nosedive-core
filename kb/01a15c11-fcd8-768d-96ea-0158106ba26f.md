# Status

The repo kind links this gate, so `nosedive pass --status <repo>` runs for any repo in the ship's kb. It reads what the repo says it is from the tip of its trunk as its remote has it now, fetched, never from the checkout, which may be behind or mid-dive; the repo is hydrated first when it is not checked out. What it says is the key its config names its root under (`ship`, `cape` or `base`), or, in an older config, its root's kind, a legacy `base` with a workspace being a ship; any other root, or no config at all, makes it `misc`. It prints one line, `<name>: its doc says <role>, it says <what it is>`, with the root's id when it has one, and fails when the two differ, or when the doc has no `role`, naming the `crud <repo> --meta` that sets it.
