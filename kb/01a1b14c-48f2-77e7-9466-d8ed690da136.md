# Legacy capes

The first migration in the chain, before [baseline](01a175db-f8d6-7926-b240-29e8caa38e94.md), whose input alone says a repo was legacy nosedive's: its config names a `backlog` and lists no `roots`. Any other repo is left as it is.

For each of two capes, the work cape (`nosedive-work`) and the legacy cape (`nosedive-legacy`, which holds legacy's `test`, `hydrate-repo.workspace`, `dehydrate-repo.workspace`, `record.gate` and `note`):

- **Repo doc**: a `kind: repo` doc of the cape's fixed id, name, origin and trunk `main` is written into the config's `kb` (`./kb` by default), unless a doc of that id is there or in `.nosedive/repos` already. Baseline then moves it into `.nosedive/repos`.
- **Worn**: the backlog doc links it `rel: .cape`, pinned with `commit:` to the commit this core names for that cape, as `pass --attach-cape` would. A backlog that links a doc of that id already is left as it is, so a cape attached by hand keeps its pin.

So seed, which builds every worn cape, gives a legacy hero jump, pack, land and bail and the commands above with no step of its own. It says what it attached. Running it again changes nothing.
