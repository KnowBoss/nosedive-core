# Write kb doc

Top-level frontmatter keys are written in KINGSMETAL order: `kind`, `id`, `name`, `gist`, `scopes`, `meta`, then any other key in its existing order, then `links` last. A doc takes that order the next time it is written; nothing rewrites docs that are otherwise untouched. A comment above the first key stays at the top, and no key is left with a blank line under the opening fence (a blank that led the new first key moves to the key under it); other blank lines travel with their key. A doc that uses YAML aliases keeps its order, since a move could put an alias before its anchor. Values, comments and nested order are untouched, so once a doc is in order a field an action changes is the only line in the diff. `kingsmetal(yaml)` applies the order alone, for crud's edit commit to compare what it would write.
