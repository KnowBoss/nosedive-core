# Edit kb docs

crud's edits all run in one. `doc(id)` finds a doc as crud does (the bridge, then the workspace's repos) once per edit, so later changes see earlier ones, and refuses a doc git does not track before anything is written. `change(doc)` marks it to be written. `commit()` writes the marked docs whose text changed and commits each repo's together. Its subject is commit-subject's for the docs written in that repo, `crud <edits>` naming the edits applied, unless it is given an action and what, as pass gives `pass` and its sect. An edit is opened with the core version its commits are co-authored under. A doc is written with its frontmatter in KINGSMETAL order, so an edit also orders the doc it touches. It refuses a doc whose scopes repeat a key as it would be written, so an edit can repair one. It returns the marked docs' paths relative to the bridge.

Before `commit()` writes anything, it revalidates every document opened by the edit, including unchanged read dependencies, across all participating repositories. The original bytes and file identity/timestamps, tracked index entry and repository HEAD must still match. Missing, replaced, touched, unstaged/staged-changed or newly committed inputs refuse the whole prepared edit with `code: REPOSITORY_CHANGED`, `status: 409`, `outcome: not_applied`. Preconditions are kept privately rather than trusting the mutable document's `text` field. A document must be opened by this edit before `change()` accepts it.

`editKbDocs(cwd, { exclusive: true })` additionally uses Windows-enforced file sharing: it opens every read-set document while denying write/delete sharing, validates bytes/index/HEAD again under those handles, writes through those same handles, flushes and commits while retaining them. A competing process cannot write, replace or delete the locked files during the operation. An already open writer causes refusal before any writes. The helper receives JSON through stdin, and messages/pathspecs go through files rather than shell-built arguments. Handles are released on completion or process death. Prepared single edits, batches and passes receive this option through `Ctx.exclusiveWrites`.

Protected mode refuses before writing on unsupported platforms. Ordinary callers that omit the option retain optimistic validation. Multi-repository Git commits are still not atomic, and an I/O or commit failure after writing can leave partial results; those failures remain unknown, not `not_applied`. The exclusion guarantee covers the opened document read set, not arbitrary unrelated files or Git metadata updates by other tools.

Before opening documents, the helper registers its actual PID/host in each Git common directory's `nosedive-writers/` registry, then checks its requesting process. Registrations remain until its document handles close and commit work finishes. A consumer must treat a live or unknown registered helper as a writer even if its parent has died; only confirmed dead helpers can be ignored. This prevents parent-lock recovery from overlapping a surviving helper. Parent exit is also checked before writes and commits.
