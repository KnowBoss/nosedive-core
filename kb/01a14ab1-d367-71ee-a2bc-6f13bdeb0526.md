# Edit kb docs

crud's edits all run in one. `doc(id)` finds a doc as crud does (the bridge, then the workspace's repos) once per edit, so later changes see earlier ones, and refuses a doc git does not track before anything is written. `change(doc)` marks it to be written. `commit()` writes the marked docs whose text changed and commits each repo's together. Its subject is commit-subject's for the docs written in that repo, `crud <edits>` naming the edits applied, unless it is given an action and what, as pass gives `pass` and its sect. An edit is opened with the core version its commits are co-authored under. A doc is written with its frontmatter in KINGSMETAL order, so an edit also orders the doc it touches. It refuses a doc whose scopes repeat a key as it would be written, so an edit can repair one. Opened with the capes the action runs with, it also refuses, before anything is written, a `.feat` link the edit adds that hangs a durable doc under one that is neither durable nor a root: a rel ending `.feat` other than `parent.feat` from a non-durable doc to a durable one, or a `parent.feat` from a durable doc to a non-durable one. A root is a doc a config's `roots` names, the hero's or the holding repo's. Links the doc held before the edit are left as they are, so an edit can still touch a doc that broke the rule before it existed. Durability is the doc's kind's, found as crud finds it (see find-kind): a kind is durable when its doc has no `## Drop when` section (or, until the drop-when migration renames it, `## Done when`), and a kind nothing declares is not durable. A new link whose rel ends `.spec` is refused from a doc that is not durable, naming its kind: specs hang only off durable docs (specs-on-durable). Opened with a way to warn, it warns of each written `kind` doc whose Drop when heading is not read as one or whose section is empty, and of one whose edit adds or removes that section, so makes its kind no longer durable or durable. It returns the marked docs' paths relative to the bridge, and records each commit it makes in `commits`, `{ repoDir, sha }` in the order made, for pass to hand to a gate's `committed` fn.
