# Read repo config

Unlike find-bridge, it never looks above the directory, so a repo checked out in a hero's workspace reads as itself. Nothing is there when the directory has no `.nosedive/config.yaml`.

A repo is what its config enables:

- `id`: the repo's quid, seeded once, which names it to everything outside it, and is its primary root's id.
- `roots`: the docs its docs hang from, as paths from the repo root, each in the directory that holds its docs. The primary root, the one whose id is `id`, else the first listed, gives the repo its kb. A hero's roots are bases, the primary its home base; a cape's is of kind `cape`; a repo of data's is a `base` too.
- `workspace`, when set: where the repos it works in are checked out; a repo with one can do work.
- `migrations`: the quids of every migration the repo has run, in the order they ran (see run-migrations).

The selected base is the root `NOSEDIVE_BASE` names, by quid, by the root doc's name or by its directory, else the primary root. Its directory, `baseDir`, is where crud writes; a `NOSEDIVE_BASE` that is the absolute path of a directory that is no root is the `baseDir` alone, and the primary stays the base whose capes are worn. Launch makes `--base` absolute when it names no root, and refuses one that is neither. The capes a base wears are its links (see configured-capes).

The kinds it declares and the repos it registers are kept in `.nosedive/kinds/` and `.nosedive/repos/`, shared by its roots.

A config without `roots` has none: its kb is `kb/`, and its workspace is its `workspace`, if it has one.
