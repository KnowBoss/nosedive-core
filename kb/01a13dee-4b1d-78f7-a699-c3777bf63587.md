# Read repo config

Unlike find-bridge, it never looks above the directory, so a repo checked out in a hero's workspace reads as itself. Nothing is there when the directory has no `.nosedive/config.yaml`.

A repo is what its config enables:

- `id`: the repo's quid, seeded once, which names it to everything outside it.
- `roots`: the docs its docs hang from, as paths from the repo root, each in the directory that holds its docs; the first root's directory is its kb.
- `workspace`, when set: where the repos it works in are checked out; a repo with one can do work.
- `capes`: the capes it imports. A root of kind `cape` is what makes it a cape itself.

The kinds it declares and the repos it registers are kept in `.nosedive/kinds/` and `.nosedive/repos/`, shared by its roots.

A config without `roots` has none: its kb is `kb/`, and its workspace is its `workspace`, if it has one. A legacy nosedive config is read only by the baseline migration, which reads it itself.
