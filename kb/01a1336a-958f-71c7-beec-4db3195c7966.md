# Launch

`nosedive <cape>:<action>` runs the action of the cape named, `nosedive-core:<action>` core's and `<hero>:<action>` the hero's own, the hero named by its root, refusing when that cape has no such action: the same grammar as crud's `<repo>:<kind>`. A bare action runs core's whatever else declares the name, then the hero's own, then a configured cape's; a name two configured capes declare, and neither core nor the hero, is refused, naming each as `<cape>:<action>`. Capes go by their full names. `help` lists core's top-level commands under core's name, then the hero's under its root's name, then each configured cape's under its own, as the manifest recorded them when it was built, or the cape as not built; an action under another action runs by name but is not listed. A gate is no command: help leaves it out, and naming one is refused with its usage. `<action> --help` lists its usages, and `--more` adds its doc's body; an action whose usage takes the command line as it is (`<argv>...`) reads its own `--help`. Errors print as `nosedive: <message>` with exit code 1.

The same file holds the types every cape is written against (`Ctx`, `ActionCall`, `Cape`, `GateCtx`) and `consoleCtx`, the ctx of a real command line.
