# Launch

`nosedive <cape>:<action>` runs the action of the cape named, `nosedive-core:<action>` core's and `<hero>:<action>` the hero's own, the hero named by its root, refusing when that cape has no such action: the same grammar as crud's `<cape>:<kind>`. A bare action runs core's whatever else declares the name, then the hero's own, then a worn cape's; a name two worn capes declare, and neither core nor the hero, is refused, naming each as `<cape>:<action>`. Capes go by their full names. Errors print as `nosedive: <message>` with exit code 1.

## Where it acts

nosedive acts on the nearest repo above the directory it runs in (see find-bridge), or on the one `NOSEDIVE_HERO` names, from anywhere: actions then run as if from that repo's directory. A workspace checkout is never a hero: without `NOSEDIVE_HERO`, nosedive refuses to run from inside one, naming the hero whose workspace holds it and how to act from there, so neither a habit nor a git hook acts on the wrong repo. The workspace directory itself acts on its hero.

`--at <target>`, before the action, selects the target: one of the hero's roots by its quid, its name or its directory's name, else any existing directory inside the hero or its workspace, relative to where nosedive acts; `seed` also takes one that does not exist yet, to make it (see seed). It sets `NOSEDIVE_AT` for everything the action reads; without it, the target is the directory of the primary root (see read-repo-config). It names the tree an action works in: crud writes new docs into it, and scaf walks it. The capes in use are those the target root wears, the primary root's when the target is a directory that is no root.

```sh
NOSEDIVE_HERO=~/mi nosedive --at kb jump <feat>
nosedive --at workspace/notes crud idea "Kept apart from the hero"
```

## Help

`help`, or no action, lists core's top-level commands under core's short name and version, then the hero's own under its root's name, then each worn cape's under its short name, the name of its cape root doc, and version, as the manifest recorded them when it was built, or the cape as not built; `--help --more` adds each cape's commit, where it was built from, and its repo's id. An action under another action runs by name but is not listed. A gate is no command: help leaves it out, and naming one is refused with its usage.

`<action> --help` prints the action's gist and usages and names `--help --more`, which adds its doc's `## Usage` section. An action whose usage takes the command line as it is (`<argv>...`) reads its own `--help`.

The same file holds the types every cape is written against (`Ctx`, `ActionCall`, `Cape`, `GateCtx`) and `consoleCtx`, the ctx of a real command line, whose directory is `NOSEDIVE_HERO` when set.

An in-process consumer can set `Ctx.failure(error)` to observe the original failure object, preserving structured status and outcome fields without parsing terminal text. The observer runs after the error is printed; launch still returns exit code 1. Ordinary CLI contexts omit it.

`Ctx.exclusiveWrites` requests enforced exclusion for prepared document edits. Shared CRUD single edits, batches and passes carry it into their common edit layer; unsupported platforms refuse protected writes before changing files.
