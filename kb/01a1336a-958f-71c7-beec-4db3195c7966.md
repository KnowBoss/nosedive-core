# Launch

`nosedive <cape>:<action>` runs the action of the cape named, `nosedive-core:<action>` core's and `<hero>:<action>` the hero's own, the hero named by its root, refusing when that cape has no such action: the same grammar as crud's `<cape>:<kind>`. A bare action runs core's whatever else declares the name, then the hero's own, then a worn cape's; a name two worn capes declare, and neither core nor the hero, runs the action of the cape that supersedes the other (see cape), and is otherwise refused, naming each as `<cape>:<action>`. Capes go by their full names. Errors print as `nosedive: <message>` with exit code 1.

## Where it acts

nosedive acts on the nearest repo above the directory it runs in (see find-bridge), or on the one `NOSEDIVE_HERO` names, from anywhere: actions then run as if from that repo's directory. A workspace checkout is never a hero: without `NOSEDIVE_HERO`, nosedive refuses to run from inside one, naming the hero whose workspace holds it and how to act from there, so neither a habit nor a git hook acts on the wrong repo. The workspace directory itself acts on its hero.

`--at <target>`, before the action, selects the target: one of the hero's roots by its quid, its name or its directory's name, else any existing directory inside the hero or its workspace, relative to where nosedive acts; `seed` also takes one that does not exist yet, to make it (see seed). It sets `NOSEDIVE_AT` for everything the action reads; without it, the target is the directory of the primary root (see read-repo-config). It names the tree an action works in: crud writes new docs into it. The capes in use are those the target root wears, the primary root's when the target is a directory that is no root.

```sh
NOSEDIVE_HERO=~/mi nosedive --at kb jump <feat>
nosedive --at workspace/notes crud idea "Kept apart from the hero"
```

## Help

`help`, or no action, lists core's top-level commands under core's short name, then the hero's own under its root's name, then each worn cape's under its short name, the name of its cape root doc, as the manifest recorded them when it was built, or the cape as not built. No version is shown: plain help is the agent surface, which must read the same wherever the same commands are built and change only when they do (versions-behind-more). `--help --more` adds each cape's version beside its commit, where it was built from, and its repo's id. An action a worn cape supersedes is listed once, under the superseding cape; `--help --more` adds `, in place of <cape>'s` to its row, naming the cape it stands in for. An action under another action runs by name but is not listed. A gate is no command: help leaves it out, and naming one is refused with its usage.

`<action> --help` prints the action's gist, then each usage with the summary of its jsdoc block, the first line of the block that opens the default export of its impl file (usage-help-from-jsdoc). A usage with no block shows nothing beside it: the gist above stands for it. `--help --more` adds under each usage its `@nosedive-<key> <value>` attributes as `<key>: <value>` lines and its hash, `u<first 8 hex of its id>`, then the doc's `## Usage` section, then says that `nosedive <action> --help --more <u-hash>` prints the rest. That form takes a hash or any prefix of it of at least 4 hex digits after the `u`, and prints the one usage's whole block: usage text, hash, summary, body, params, returns and attributes; a usage with no block prints its gist and says it has none. A prefix no usage has, or more than one does, is refused, naming the usages it matches (or all of them when none). An action whose usage takes the command line as it is (`<argv>...`) reads its own `--help`; pass does, and lists the same for its gates.

```text
seed [--no-capes] [--root-kind <kind>]
  Makes the current git repo a bridge, or brings its setup up to date.
  feat: 01a1336b-c0b8-7cde-b7c6-285196062297
  hash: ue4a628f2
```

The same file holds the types every cape is written against (`Ctx`, `ActionCall`, `Cape`, `GateCtx`; a `CapeDoc`'s usage carries its block as `description`, read when the cape is described, absent in a build that predates it), `renderActions`, the help listing that agent-surface writes (plain, without `--more`), `usageHelp`, which renders usages and one usage's block for `<action> --help` and for pass, and `consoleCtx`, the ctx of a real command line, whose directory is `NOSEDIVE_HERO` when set.
