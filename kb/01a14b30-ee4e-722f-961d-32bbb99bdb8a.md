# Pass

Behaviour that belongs to a kind lives in gates, not in crud or a command of its own. `nosedive pass --<sect> <quid> ...` runs every gate linked as `<sect>.gate`, first from the doc's kind doc, then from the doc, each in link order and each once. A rel is `<sect>.<role>`: the role says what the target is to the doc, the sect which of them.

pass knows no sect itself. It takes its command line as it is, and matches it against the docopt usages that the gates of core and of every built cape declare, each starting `pass --<sect> <quid>`; the usage that matches names the sect, and what it binds, besides the sect's quid, is the args every gate gets. `pass` or `pass --help` lists those usages, and a command line none matches is refused with them.

Gates run in order and the first that throws stops the pass. They edit docs through the pass's edit, with crud-edit, so when all pass, each repo gets one commit, `pass(<name>): <sect>`, and when one fails nothing is written. `pass --test <quid>` on a cape's root runs its tests, since the cape kind links core's test gate.
