# Run migrations

Brings a repo to today's shape by running the migrations it has not run. Config `migrations` lists the quids of every migration the repo has run, in the order they ran. A config from before the list has `last-migration` instead, read as having run that migration and every one before it in the chain.

It runs every migration core has that the list lacks, in chain order, each committed alone as `migrate: <name>`, with the nosedive co-author trailer with its quid appended to the list. The first commit also drops `last-migration` for the list; when no migration runs, a config with `last-migration` is converted alone, in a commit of its own. A migration that changes nothing is still run, so its commit holds only the list. A quid the list holds that core does not have was run by a newer core, so it refuses, naming it. A repo with no config has nothing to migrate. A migration may decline to run yet, returning nothing after saying why: it is not recorded, the migrations after it wait too, and the run ends without an error. It returns the names of the migrations that changed something.

To run a migration again, a repo removes its quid from the list and seeds, so every migration must be safe to run on a repo it has already changed. A migration is given the capes core is running with and a way to tell the pilot something.
