# Legacy repo meta

Legacy nosedive's repo docs keep their remote in `meta.remotes.cloud`, often scp-style, and their trunk in `meta.default-branch` or `meta.base-branch`; core's hydrate-repo reads `meta.remotes.origin` and `meta.trunk`, and takes an scp-style remote for a path unless it starts `git@`. This migration rewrites each repo doc in `.nosedive/repos` to core's keys:

- **Origin**: with no `remotes.origin`, `remotes.cloud` becomes it, an scp-style `user@host:path` written `ssh://user@host/path`, and `cloud` goes. A remote in any other form is moved as it is. With an origin already, `cloud` is left alone.
- **Trunk**: with no `trunk`, `default-branch`, else `base-branch`, becomes it. Both go either way, since `trunk` is what core reads.

Everything else is kept, `meta.path` included: core checks a repo out at `<workspace>/<name>` whatever it says. A doc with nothing to rewrite is left as it is, so the migration is safe to run again, and it says how many docs it rewrote.
