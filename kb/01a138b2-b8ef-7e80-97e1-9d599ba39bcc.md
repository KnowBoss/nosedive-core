# Check meta

The kind comes from the given kbs first, in order, then the loaded capes, core first, then the ship's configured capes (see find-kind). A kind nothing declares is not an error: it returns a warning, and the meta goes unchecked. A meta that breaks the schema throws, listing every problem.

## References to docs of a kind

A string property can declare `kind: question` alongside `type: string`.
The value must be a quid resolving to an existing doc of that kind, searching
the doc's own kb and the ship's kb first, then the ship and its workspace,
then loaded capes. Missing docs, invalid
quids and wrong kinds fail validation at the property's path. In a CRUD batch,
references see the final in-memory kind of every edited target, regardless of
edit order; a failure writes nothing. This validates outgoing references when
the owning doc is validated, not all incoming references when a target changes
or is deleted.

For a separate decision doc, the kind's schema can contain:

```yaml
type: object
additionalProperties: false
required: [question, answer]
properties:
  question:
    type: string
    kind: question
  answer:
    type: string
    minLength: 1
```
