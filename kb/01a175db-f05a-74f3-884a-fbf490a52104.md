# Migration

A step that brings a repo from one shape to the next, small and one of many. Its code is beside it, as a function's is: `src/i<id>.ts`, taking the repo's directory and returning the files it changed, with its tests. Its `meta.after` names the migration it builds on; the first has none. Migrations form one chain: two after the same one, or a migration naming one that is not there, is an error core's tests catch.

Seed runs them, every time, before anything else: those after the repo's config `last-migration`, or all of them when it has none, in order (see run-migrations). Each must leave a repo already in its shape as it is, since a repo seeded before migrations existed has no `last-migration`.
