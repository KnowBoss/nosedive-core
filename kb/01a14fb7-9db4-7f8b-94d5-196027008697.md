# Builds a hero's own actions from its working tree into .nosedive/capes/<id>.js and loads them, or returns nothing when it has none

The bundle's `owner` is the hero's id and its `shortName` its root's name. The hero's own kinds are its, so no group of kinds is made of this cape.

## Whole

Like a cape, a hero's code builds whole: its npm packages are installed with install-cape-packages first, and the build id covers its lockfile and every file under `assets/` as well as its code docs and `src/`.

## Imports

A hero's code imports as a cape's does, through build-cape's `capeImports` (one-build-path): core's actions by id and its named exports by name, and any cape it imports, built first at the ref the hero uses for it, whose build is part of the id. An import its target lacks, or an action it uses that its docs do not link, refuses the build, as for a cape. So `pass --test` run from a cape's own repo, which builds it this way, takes what seed's build of the same source takes.
