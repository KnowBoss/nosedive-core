# Action

An action doc is the only way into a cape's code: find the action in the backlog tree, read its doc, then go to the files its id and usages name.

## Fields

- `name`: what users type (`crud`, `record.dive`), or a friendly description for an internal function (`match-usage`).
- `gist`: one line on what it does.
- `meta.usages` (optional): the contracts a user action supports, in docopt notation: `<arg>`, `<arg>...` (one or more), `[ ... ]` (optional), `--flag`, `--option <value>`. Each starts with the name. A value of `-` means stdin, by convention of the impl that reads it. A doc with no `meta.usages` is an internal function, which users cannot invoke.

```yaml
meta:
  usages:
    - crud <quid>
    - crud <quid> --meta <source>
```

The body says what the action is for and how to use it.

## In the tree

Actions are feats by their links: the backlog root links each user action as `rel: action.feat`, and each action links the internal functions it uses as `rel: child.feat`; each links back to its parent with `rel: parent.feat`. An internal function hangs under the one action it serves first, so every action has exactly one place in the tree.

## Files

With `h` = the doc id without dashes, and `u` = `uuidv5(<usage text, whitespace collapsed>, <doc id>)` without dashes:

| File | Exports | Holds |
|---|---|---|
| `src/a<h>.ts` | `a<h>` | The entrypoint. With usages: validates the matched usage's arguments and calls its impl. Without: the function itself. |
| `src/i<u>.ts` | `i<u>` | One usage's impl. |
| `test/t<u>.test.ts` | | That usage's tests, driven through the launcher with real arguments, so they prove the usage is reachable. |
| `test/t<h>.test.ts` | | An internal function's tests. |

Code imports an action by its export, named for what it does where it is used: `import { a01a1335482437c9eb145885f65f12aa1 as matchUsage } from "./a01a1335482437c9eb145885f65f12aa1.ts"`. To learn what one does, read `kb/<its id, dashed>.md`. From another cape, the module is that cape's repo name, `nosedive-core` for core, and the action doc must link what it imports as `<repo>:<doc id>`.

Rewording a usage changes `u`, so its impl and test must move: a contract never changes silently. `nosedive scaf` writes the missing files; the check refuses a usage without its impl or test, and any file no doc accounts for.

## In a cape

A cape exports `id`, `name`, `commit`, `version`, `docs` and `index`, and, when built by seed, the `core` and the capes it `needs`. With `K` the cape id, `index[uuidv5(<name>, K)]` is the doc id of the action named `<name>`, and `index[uuidv5(<doc id>, K)]` is its entrypoint. `K` covers the commit, the core and every cape imported, so code built against another build never finds a stale entry.
