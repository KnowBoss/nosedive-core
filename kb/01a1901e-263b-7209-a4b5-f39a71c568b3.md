# Feat tree

One definition of what a feat is and which dives are open, for core's commit-subject and for the work cape, so crud and the loop never name different feats.

`featWalk` walks once from the hero's roots, a root of kind cape aside, following links whose rel ends `.feat` except `parent.feat`, and reads only the docs it reaches. It returns the feats it reached, each with the directory of the root that reaches it and the docs that link it so, and every doc it read, so a caller asks no doc twice. `featTree` is its feats alone. `featRoot` is the directory of the root that reaches a feat. `linkedIds` is the ids a doc links within its own repo, with each link's rel; a link naming another repo (`<repo>:<id>`) is left out.

`openDives` are the docs of kind `dive` the walk reached, which a feat links as `dives.feat`, with no `meta.outcome`. `heldDives` are those whose `meta.diver` is a holder token, which `holderToken` computes for a checkout of the hero (see commit-subject).
