# Crud gates

A kind keeps its docs in shape however crud changes them by linking a gate `crud.gate` (crud-gate-timing); a doc can link one so too. The gate's usages say when it runs: `before crud <kind>` or `after crud <kind>`, the kind spelled and matched as pass matches a gate's (see gate-usage, pass).

`runCrudGates(when, edit, touched, ctx)` runs, for each doc one crud command touched, the gates its kind and its own links name for that `when`, once each, in link order, the kind's first. A touched doc is its id with `before` and `after`, each `{ fm, body }` or missing: missing before for a doc minted, missing after for one dropped (crud-gate-state). A gate reads what happened from the two; `changed(before, after, path)` says whether a dotted path of the frontmatter, `meta.feat`, differs between them.

Each gate is called as pass calls one, with a `GateCtx` that also carries `when`, `before` and `after`, its doc being the touched one as the edit holds it (the dropped one for a drop). A before gate refuses by throwing; its `crud` and `mint` throw, so it writes nothing. `committed` is pass's alone: a crud gate's `GateCtx` has none, so its `committed` is undefined, and a gate written for both checks it. An after gate edits through the same edit, with `crud` and `mint`, and what it changes is committed with crud's own change; edits a gate makes run no gates. The worn capes are loaded as pass loads them, and only when a touched doc's kind or links name a crud gate.

Crud calls it in each of its writes: an edit, a kind change and a batch run before gates and then after gates once the edits are made in memory and before the commit; a mint runs both once the doc is minted, before its commit, so a failure removes it again; a drop runs before gates only, before anything goes.
