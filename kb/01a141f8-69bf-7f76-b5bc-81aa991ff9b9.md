# Configured capes

The capes a hero wears are its selected base's links whose rel's role is `cape`, each to a repo doc: `.cape` while no sect is wanted. A link's `ref` pins the cape to a branch, tag or commit; without one it follows the trunk. The cape's name is its repo doc's name, which is also the name of the cape's root. A cape's build is the newest the manifest records for that repo with this core, at that commit when the ref is 40 hex characters, or for that ref otherwise; it has none until seed or `pass --don-cape` builds it. A link to a doc that is no repo is refused.

```yaml
links:
  - .nosedive/repos/<quid>.md:          # nosedive-example-cape, at its trunk
      rel: .cape
  - .nosedive/repos/<quid>.md:          # nosedive-other-cape, pinned
      rel: .cape
      ref: <commit>
```

Each root wears its own capes, so which ones are in use follows the base selected: the home base unless `--base` names another (see launch).
