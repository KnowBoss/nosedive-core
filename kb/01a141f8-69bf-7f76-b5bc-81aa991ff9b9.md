# Configured capes

Config `capes` lists each cape as `<repo>` or `<repo>@<ref>`, the repo by its name in the bridge kb, which is also the name of the cape's root. A cape's build is the newest the manifest records for that repo with this core, at that commit when the ref is 40 hex characters, or for that ref otherwise; it has none until seed or `cape` builds it. A repo the kb does not have, or cannot clone, has no repo doc here, and seed is where that fails loudly. Listing a repo twice is refused.

```yaml
capes:
  - nosedive-example-cape            # its trunk, as of the last seed
  - nosedive-other-cape@<commit>     # pinned
```
