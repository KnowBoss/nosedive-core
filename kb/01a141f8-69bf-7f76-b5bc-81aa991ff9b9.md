# Configured capes

The capes a hero wears are its target root's links whose rel's role is `cape`, each to a repo doc: `.cape` while no sect is wanted. A link's `ref` names what the cape follows, a branch, tag or commit, or the trunk without one; its `commit`, the sha `pass --attach-cape` resolved that to, pins it (cape-pin). Builds use the `commit` when the link has one, else the `ref`, whether or not the hero's workspace holds a checkout of the repo (pin-always-wins). The cape's long name is its repo doc's name; its short name is the cape root doc's name. Repo links resolve only in `.nosedive/repos/`, by place regardless of root kind. A cape's build is the newest the manifest records for that repo with this core, at that commit when what builds use is 40 hex characters, or for that ref otherwise; it has none until seed or `pass --attach-cape` builds it. A link to a doc that is neither a repo doc nor a local cape's root is refused. A `supersedes.cape` link is no worn cape, though its role is `cape` (see cape): it names a cape by its seeded id, and is skipped here.

`providers` says which of the worn capes' builds, the configured capes' `build.supersedes` read against `build.owner`, answer for an action: those that provide it less those another provider supersedes, `dropped`; a cape superseding itself through others is `cyclic`, as two superseding each other are, and then nothing is dropped. Only worn capes count, so a supersedes naming a cape not worn changes nothing. Launch and find-cape use it.

A local cape (local-cape-shape) is linked by its cape root doc, keyed by that doc's path from the hero, such as `tools/spec/kb/<quid>.md`, with rel `.cape` and no `ref`. A key is a local cape when it names no repo doc and it is the root of one of the hero's local capes (see local-capes): a root its config lists, of kind `cape`, held by a nested seeded directory. Its name is that root doc's name and its repo id the root doc's quid; it has no remote, and its build is of its working tree (see build-cape), so its build is current by the files in its directory, and `pass --attach-cape <dir>` builds it.

```yaml
links:
  - .nosedive/repos/<quid>.md:          # nosedive-example-cape, at its trunk
      rel: .cape
  - .nosedive/repos/<quid>.md:          # nosedive-other-cape, pinned
      rel: .cape
      ref: <commit>
```

Each root wears its own capes, so which ones are in use follows the target: the primary root unless `--at` names another root (see launch); an `--at` that is a plain directory wears the primary root's.
