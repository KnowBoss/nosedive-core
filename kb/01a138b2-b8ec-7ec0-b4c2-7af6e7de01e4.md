# Gate

A gate is code a doc passes through: it lives where all code does, `src/i<id>.ts`, exporting `i<id>(ctx)`, and throws to fail. Passing may change things: its ctx, a `GateCtx`, holds the core, the other loaded capes, the bridge, the doc, the options its usage matched besides the sect, the pass's edit, `crud` to edit docs in it, and `out`/`err`. A gate's `meta.usages` are docopt usages, each starting `pass --<sect> <quid>`: they are how pass reaches it.

A gate is linked as `<sect>.gate` by a doc, or by a kind for every doc of it: the cape kind links core's test gate, so `nosedive pass --test <root>` runs any cape's tests. A gate has no test file of its own, because it is one; and users cannot run it by name.
