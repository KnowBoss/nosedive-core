# Dock

## Usage

`dock <ref>` checks a repo out outside any workspace, at `~/.nosedive/docks/<docker>/<repo doc name>` (`NOSEDIVE_USER_DIR` in place of `~/.nosedive`), where `<docker>` is the docking hero's primary root's name (dock-in-core). It runs in a hero, from any branch or checkout of it, and leaves the hero as it is. `<ref>` is tried in this order (dock-usage-shape):

1. A quid: a repo doc of the hero's, docked as a repo; else a doc of the hero's kb or its workspace's, docked as a feat.
2. A git remote, matched against each repo doc's `meta.remotes.origin` however either is spelled: scp form (`git@host:owner/name`), `ssh://`, `https://`, with or without a user, `.git` or a trailing slash, the host in any case.
3. A repo doc's `name`.

A ref none of these finds is refused, as is one that finds more than one repo doc, naming them.

Each repo is fetched into the user's cache of it, kept and keyed by its origin as hydrate does (user-cache-by-remote), the bare clone made when there is none; its trunk is the repo doc's `meta.trunk`, as hydrate reads it.

**A hero repo** is one whose trunk holds `.nosedive/config.yaml` with a primary root of kind `hero` (the root whose quid is the config's `id`, else its first). It is docked as before (dock-by-docker): on the branch `<docker id>/dock`, the docking hero's config id, a worktree of the cache starting at `origin/<trunk>` and tracking it, so the dock pulls from and pushes to trunk; the cache's `push.default` is set to `upstream`. A dock already there on that branch is fast-forwarded to `origin/<trunk>`; one that cannot be is left as it is, and dock says why.

**Any other repo** is docked read-only (dock-read-only-detached): a worktree of the cache with a detached HEAD at `origin/<trunk>`.

**A feat** is docked by its `scopes`: each entry's repo doc, read-only, detached at `origin/<work-branch>` when the entry records a `work-branch` (feat-dock-head), else at `origin/<trunk>`. A work branch the remote does not have is docked at trunk, and dock says so. A hero repo in a feat's scopes is docked read-only too. An entry for a kind's owner, one carrying `canonical`, `version`, `schema` or `meta` (kind-model), names no repo and is passed over. A feat whose scopes name no repo is refused, as is any other entry naming no repo doc of the hero.

`dock <ref> --head <head>` docks each repo `<ref>` finds read-only, detached at `<head>`: `origin/<head>` when the cache has that branch, else `<head>` as git reads it in the cache (a tag or a commit). A hero repo docked with `--head` is read-only. A head a repo does not have is refused.

Docking a read-only dock again moves its detached HEAD to the new head. It refuses a dock whose tree is dirty, naming its changed and untracked files; for a feat, every dock is checked before any is moved, so a refusal moves none. A dock at the path that is not a worktree of the repo's cache, or is of the other kind (on a branch where a read-only dock is wanted, or detached where a hero dock is), is refused: move it first.

dock builds nothing (global-core-build). For each repo it prints the dock's path, its branch or the ref it is detached at, and its commit; for a hero dock, that `nosedive seed` there builds its capes.
