# Dock a hero

## Usage

`dock <repo>` docks the hero a repo doc of this hero names (dock-by-docker). `<repo>` is the doc's quid, or a git remote matched against each repo doc's `meta.remotes.origin` however either is spelled: scp form (`git@host:owner/name`), `ssh://`, `https://`, with or without a user, `.git` or a trailing slash, the host in any case.

1. It fetches the repo into the user's cache, `~/.nosedive/cache/<repo id>.git` (`NOSEDIVE_USER_DIR` in place of `~/.nosedive`), as hydrate keeps it, making the bare clone when there is none. The cache's `push.default` is set to `upstream`.
2. It reads `.nosedive/config.yaml` at `origin/<trunk>`, the trunk the repo doc's `meta.trunk` names, else main, and the primary root doc that config names: the root whose quid is the config's `id`, else its first. It refuses, naming which, a trunk with no config, with no root, or whose primary root is no `hero`.
3. It checks the trunk out at `~/.nosedive/docks/<hero name>/<repo doc name>`, the docking hero's primary root's name, a worktree of the cache on the branch `<hero id>/dock`, the docking hero's config id, starting at `origin/<trunk>` and tracking it, so the dock pulls from and pushes to trunk. Any branch or checkout of the docking hero docks there.
4. A dock already there that is a worktree of the cache on that branch is fast-forwarded to `origin/<trunk>`; one that cannot be is left as it is, and dock says why. Any other directory there is refused.

It prints the dock's path, its branch and commit, and that `nosedive seed` there builds its capes.
