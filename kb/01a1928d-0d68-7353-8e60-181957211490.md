# Hero self

After canonical-kinds, a repo with config workspace has its primary root (config id, falling back to the reader primary) changed from core kind base to core kind hero. The root path and config roots never change, and additional roots, capes, repos without a workspace and primary roots of another kind are untouched. It preserves meta, title, body, links and unrelated scopes; core canonical version and schema are replaced by the hero kind pin. It waits without writing while the hero schema cannot be pinned to a published version. An already migrated hero is unchanged. Seed makes this migration pending again when --workspace first enables work on an existing repo, so a prior no-op on a data repo does not prevent promotion to hero. The migration runner records its quid and commits the change once.
