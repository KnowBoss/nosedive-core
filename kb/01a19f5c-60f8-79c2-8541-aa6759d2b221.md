# Agent surface

Every agent working in a hero reads the command surface the hero really has, from its instruction files, stamped with the core that wrote it. Seed writes it, passing in launch's rendering of `help` (see seed); next reports a block that no longer matches (see next). Both use it, so it hangs in the repos lib group.

## Which directory

Only a hero has a surface: a repo with a root of core's kind hero, at the top of its own git checkout, one holding `.git`; a workspace alone does not make one, since core, a cape, has one too. `hasSurface(dir)` answers it, asked by seed before it writes and by next before it checks, so a cape, core included, a base, and a local cape, which lies in the hero's checkout, are neither written nor reported: none is worked in from its own root (surface-heroes-by-kind).

## Files and markers

The instruction files are `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and `.github/copilot-instructions.md`, in that directory: one list, `INSTRUCTION_FILES`, read by the write and the drift check alike. A file takes part only when it holds both markers, `<!-- BEGIN nosedive managed instructions -->` then `<!-- END nosedive managed instructions -->`, each on a line of its own and outside any fenced code block, the same markers legacy nosedive used. Only the first such pair counts. Text outside them is never touched, and the block is never added to a file that exists without them.

## The block

Given the directory, the surface (the text of `nosedive help` as the hero sees it from its primary root: plain help, since `--more` names local capes by absolute path, and the block must read the same on every machine with the same builds; versions stay behind `--more` too, so the block changes only when the commands do (versions-behind-more)) and core's version, the function replaces what lies between the markers of every marked file with:

1. the stamp, `<!-- nosedive v=<core version> surface=<digest> -->`, the digest being the first 8 hex of the sha256 of the surface, trimmed, so two cores rendering the same block agree;
2. the fence line, the same in every hero: this hero runs nosedive core, whose `nosedive help` begins `Usage: nosedive [--at <target>] <action>`; an agent whose help begins `Usage: nosedive <command>` has legacy nosedive, whatever else the file says about installing it, and is told to stop, run no nosedive command in the hero, and ask the pilot to install core (see legacy-fence);
3. the surface, fenced with one more backtick than the longest run of backticks in it, and at least three.

The block's lines end as the file's do: `\r\n` in a file that uses it.

When none of the four files exists, it creates `AGENTS.md` holding the markers and the block. When files exist and none is marked, it writes nothing and returns a hint naming the files it looks for and the two marker lines to paste into one, then to run seed again. It returns the paths it changed, a file whose block already reads the same being unchanged, and the hint, if any; it commits nothing.

`ownChange(path, text)` says whether a file it wrote differs from what git's HEAD holds only inside the block, or is an `AGENTS.md` it created: only then may seed commit it, so a pilot's uncommitted edits around the block are never committed in nosedive's name.

## Drift

`surfaceDrift(dir, render)` returns one line for each marked file whose block's stamp digest differs from the surface's, or which carries no stamp: `warning: <file>'s agent instructions do not match this nosedive: run nosedive seed`. Only the digest is compared: the stamp's version is for reference (drift-in-next). `render` gives the surface and is called only when some file is marked, so a hero with none pays nothing. Each line is advice, `warning:`, never a `nose:` call to attention. Which side is stale is not asked: seed always renders what is installed. Unmarked and missing files say nothing.
