# Next

## Usage

`nosedive next` lists what is left to do in the hero, for the pilot and the agents working with them. It writes nothing but its record of npm's answer, `.nosedive/local/npm-latest`, which git ignores.

### Trunk first

When the hero has an `origin`, next first fetches it and compares `HEAD` with origin's trunk (`origin/HEAD`). If `HEAD` lacks commits trunk has, it prints `warning: the hero lacks <n> commits origin's trunk has: rebase onto <trunk> before trusting this list` on stderr before the list, which keeps stdout to itself, still lists, and exits 1, saying on stderr that the hero is behind, since a stale hero lists work already done elsewhere and misses work minted there. A hero with no `origin` is listed as it is, and so is one whose `origin` cannot be fetched, offline say, with a line on stderr saying so and why.

Next also checks the hero's footing, with `warning:` lines on stderr before the list that never change its exit code:

- When the repo is a hero (see agent-surface), each of its marked agent instruction files whose block no longer matches the surface this core renders for its primary root, whatever `--at` names, gets a line from agent-surface's drift check, saying to run `nosedive seed` (drift-in-next).
- Once a week, it asks npm for the version published as `nosedive` (`https://registry.npmjs.org/nosedive/latest`, or the URL `NOSEDIVE_NPM_LATEST` names), and when that version's `y.m.d` is newer than the running core's, it prints `warning: nosedive <published> is published; you run <running>: npm i -g nosedive` (npm-weekly-check). A check that got an answer is recorded, with the date and the version, in `.nosedive/local/npm-latest`, so the next is a week later; one that fails, offline say, says nothing and is tried again on the next run, as is one recorded with a date ahead of now or a record it cannot read; one it cannot write still counts. A block it cannot read is left out of the drift check rather than failing next. A core whose version is no `y.m.d`, as when run from source, is not checked.

### What it lists

It walks the hero's roots once (see feat-tree) and lists two things:

- **Leaves**: each doc the walk reaches whose kind is not durable and that links no `.feat` child of its own, other than by `parent.feat`. A feat's dives are linked `dives.feat`, so each is a leaf of its feat. A durable doc hangs only off a root or another durable doc (see kind), so every non-durable doc is work on the way to something kept, and a leaf is where that work stands.
- **Kind-declared links**: a kind's declaration may name rels in `meta.next`. A doc of that kind, not durable, that a walked doc links by one of them is listed under that doc, though the walk never follows the rel. A question kind that names `open.spec`, as mi's does, lists a feat's unanswered questions under it.

A doc linked by any other rel, such as a memo linked `<sect>.note`, is never listed.

### Output

Each listed doc is printed under the doc that reaches it, the feat or root that links it, in the order the walk met them:

```text
<parent name>  <parent path>
  <kind> <name>  <path>
```

Paths are from the hero, with forward slashes, and a kind is named by its shortest spelling: bare for the hero's own, else by its owner's short name, as `core:memo`. No done condition is printed (next-lists-droppable): what done looks like matters once a doc is picked, and is read then, from the doc and its kind's Drop when. When it lists anything, it ends with one line on how to finish what it lists: `pick one; its kind's Drop when, which crud --drop quotes when it refuses, says what dropping it takes; then: nosedive crud --drop <quid>`. With nothing to list, next prints `nothing left to do`.

### Working the list

next only lists, as a prompt for agents helping the pilot pick what to do. Working a listed doc ends in dropping it: the agent does what the doc and its kind's Drop when call for, then drops it with crud once the pilot agrees, never unasked; crud refuses a doc anything still links, and then quotes its kind's Drop when. A dive is dropped with its feat's `dives.feat` link: `crud <feat> --links` setting the dive's entry to null, then `crud --drop <dive>`.
