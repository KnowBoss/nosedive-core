# Scaf

## Usage

`nosedive [--base <dir>] scaf [<quid>]` walks the tree `--base` names, any directory `--base` accepts (see launch): the home base by default, and the hero's own directory for everything, local capes and workspace checkouts included. A walk never enters `node_modules`, `.git` or `.nosedive/capes`. `scaf <quid>` takes that one action instead, wherever its doc lives: found as crud finds a doc (see locate-kb-doc), else under the hero's directory, where a local cape's docs are.

Each action doc found is scaffolded in the seeded repo holding it, the nearest `.nosedive/config.yaml` up from the doc, looking no further than the git checkout the doc is in. An action doc is one of core's action, function or migration kinds (see doc-kind), however its repo spells it. For each, scaf writes the missing entrypoint, usage impls and tests as stubs in that repo's `src/`, and never overwrites a file. It rewrites each doc's `## Code` section, which links those files. It then lists what it could not fix by itself: an entrypoint that does not call one of its usage impls yet, and files no doc accounts for.

A repo must be a cape (a root of kind `cape`) or a hero (it has a workspace). An action doc in a repo that is neither, or in no seeded repo, is reported under `skipped` and not written; for `scaf <quid>` that is a refusal.

Output groups what was written and what is left per repo, by the repo directory's name:

```text
my-hero:
  created src/i01a1...ts
  updated kb/01a1...md
  still to do:
    ...
skipped:
  kb/01a1...md: in no seeded repo
```

The stubs throw or are marked todo, so a scaffolded action builds and fails loudly until it is written.
