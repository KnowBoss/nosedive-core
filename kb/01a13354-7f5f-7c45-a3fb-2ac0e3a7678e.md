# Scaffold cape

Seed calls it on a repo with a cape root, core included, so a cape's code files exist as soon as its docs call for them (seed-scaffolds-capes); it was the scaf action until seed took it over.

`scaffoldCape(repoDir)` walks the repo, never entering `node_modules`, `.git` or `.nosedive/capes`, and never following a symlink or junction, and takes each action doc it holds: one of core's action, function or migration kinds (see doc-kind), however the repo spells it. A seeded repo nested in it, as a local cape in a hero, is its own, and is scaffolded when it is seeded.

For each, it writes the missing entrypoint, usage impls and tests as stubs in the repo's `src/`, and never overwrites a file; a gate's usage gets an impl taking the pass's `GateCtx` and no test, a crud gate's a test too. It rewrites each doc's `## Code` section, which links those files (see code-section). The stubs throw or are marked todo, so a scaffolded action builds and fails loudly until it is written.

A usage impl it creates opens its default export with a jsdoc block (usage-help-from-jsdoc), which describe-cape-source reads and help shows: a summary line, the action doc's gist; a body line asking the author to describe what the usage does; an `@param` for each argument of the stub, `args` (naming the placeholders the usage text has) and `ctx`, or just `ctx` for a gate; `@returns`; and `@nosedive-feat <quid>`, the quid a `parent.feat` link of the action doc names, left out when the doc has none. A file that exists is never touched, so a usage written before this has no block until someone writes one.

It returns the files it wrote, from the repo, and lines saying what it did: `created <file>`, `updated <doc>`, `error <doc>: <why it could not be read>` for a doc it named and left, `error: <why>` when the repo's docs cannot be read together, `not followed: <path>` for a symlink to a directory or named as a doc, then `still to do:` and what the cape check finds that it could not fix itself, as an entrypoint not yet calling one of its usage impls or a file no doc accounts for; `nothing to scaffold` stands alone when there is nothing to write, say or fix.

A usage whose text changes changes its impl's file name, which is its id: the new file is written, and the old one is left for the check to name as a file no doc accounts for.
