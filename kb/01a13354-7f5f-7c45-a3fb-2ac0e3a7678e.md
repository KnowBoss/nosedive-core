# Scaf

## Usage

`nosedive [--at <dir>] scaf [<quid>]` walks the tree `--at` names, any directory `--at` accepts (see launch): the primary root's by default, and the hero's own directory for everything, local capes and workspace checkouts included. The usage line stays `scaf [<quid>]`: `--at` is the launcher's, given before the action (its `Usage: nosedive [--at <target>] <action>` already shows it), and the usage line names the impl files. A walk never enters `node_modules`, `.git` or `.nosedive/capes`, and never follows a symlink or junction. `scaf <quid>` takes that one action instead, in any case, wherever its doc lives: found as crud finds a doc (see locate-kb-doc), else under the hero's directory, where a local cape's docs are. Anything but a quid is refused before a lookup.

Each action doc found is scaffolded in the seeded repo holding it, the nearest `.nosedive/config.yaml` up from the doc, looking no further than the git checkout the doc is in, from whichever of that repo's roots, or other directory, holds the doc. An action doc is one of core's action, function or migration kinds (see doc-kind), however its repo spells it. For each, scaf writes the missing entrypoint, usage impls and tests as stubs in that repo's `src/`, and never overwrites a file. It rewrites each doc's `## Code` section, which links those files. It then lists what it could not fix by itself, as far as the repo's primary kb goes: an entrypoint that does not call one of its usage impls yet, and files no doc accounts for.

A repo must be a cape (a root of kind `cape`) or a hero (it has a workspace). An action doc in a repo that is neither, or in no seeded repo, is reported under `skipped` and not written. For `scaf <quid>`, that, a doc that cannot be read and any other note below is a refusal, exit 1, and nothing is written.

The output groups what was done per repo, named by its path from the hero, or by the hero's own name for the hero, then what was skipped. Every line is one of these, a path being from the repo for a repo's lines and from the hero under `skipped`:

```text
my-hero:
  created src/i01a1...ts
  updated kb/01a1...md
  error kb/01a1...md: <why the doc could not be read>
  error: <why the repo's docs could not be read together>
  not followed: <a symlink or junction to a directory, or named as a doc>
  still to do:
    <what the check found>
  nothing to scaffold
capes/local:
  ...
skipped:
  kb/01a1...md: in no seeded repo
  kb/01a1...md: <repo> is neither a cape nor a hero repo
  error kb/01a1...md: <why the doc could not be read>
  not followed: <path>
```

`nothing to scaffold` stands alone in a repo with nothing to write, say or fix. A doc that cannot be read, such as one with two canonical scopes, is named and left; the rest are still scaffolded, unless the error is that the repo's docs cannot be read together.

The stubs throw or are marked todo, so a scaffolded action builds and fails loudly until it is written.
