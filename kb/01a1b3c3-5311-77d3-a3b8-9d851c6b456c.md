# Legacy fence

Legacy nosedive reads `compatibility-level` from `.nosedive/config.yaml` and takes 2, its own, for current. A migrated legacy hero keeps that 2, so an agent with legacy nosedive installed is told by its preflight that the instructions drift, "Run: nosedive seed", and legacy's seed writes its surface back over core's.

This migration, the last of core's chain, sets `compatibility-level: 3` on a config whose level is a number below 3. Legacy nosedive then refuses to seed, since it will not write a lower level over a higher one, and its preflight says the hero was seeded by a newer package, to upgrade rather than re-seed. Core reads no level. A config with no `compatibility-level`, or one at 3 or more, is left as it is, so the migration is safe to run again.

The agent surface carries the other half of the fence: its first line tells an agent whose `nosedive help` is legacy's to stop and ask the pilot to install core (see agent-surface).
