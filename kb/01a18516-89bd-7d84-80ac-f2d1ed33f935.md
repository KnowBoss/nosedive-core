# Attach cape

## Usage

A repo kind gate: `<repo>` is the quid of the repo doc `crud repo` registered. It clones the repo's origin where build-cape keeps its sources, refuses it unless its root is a `cape`, builds it against the running core at `--ref`, or its trunk, and links the repo doc from the target root as `.cape`, carrying `ref` when given. A cape the target root already wears is refused. The repo doc's name is the hero's own for the cape, its long name, whatever the hero called it; its short name is its root doc's, which only the cape chooses (cape-short-names). It prints the version and commit it built.

A local cape is attached by `pass --attach-cape <dir>`, a gate on core's `cape` kind: `<dir>` is the path, from where nosedive runs, of a local cape, a directory of the hero seeded as a cape and listed in its config roots (see seed and local-capes), which pass reads as the quid of its root doc. It builds the cape from its working tree and links its root doc from the target root as `.cape`, keyed by its path in the hero (see configured-capes). It takes no `--ref`. A cape the target root already wears is refused, as is a directory that is no local cape, which the refusal says how to make with `seed --at`.

To detach a registered cape, `pass --detach-cape <repo>`; to forget the repo too, `crud --drop <repo> --hard`, since repo is a durable kind.
