# Hydrate

The repo kind links this gate, so `nosedive pass --hydrate <repo>` checks out any repo in the bridge's kb. The bridge keeps one bare cache per repo at `.nosedive/cache/<repo id>.git`, or `<repo id>` alone where legacy left one (legacy caches turn on per-worktree config, so each new worktree is told it is not bare), which seed has git ignore, and only the workspace holds checkouts: each is a worktree of its cache at `<workspace>/<name>`, detached at the tip of the repo's trunk: `meta.trunk`, else the branch the source's HEAD names.

The cache alone owns the trunk branch, and each hydrate fast-forwards it to the fetched tip; a trunk that has moved apart from its remote is left as it is, with a warning. No checkout has a branch of its own, so a bare `git push` fails on purpose: a push names where it goes, as `git push origin HEAD:<branch>`, `origin` being the cache's remote for the repo's first remote, which hydrate sets when the cache has none.

Each hydrate fetches the cache's branches as `origin/*`, from the repo's home copy when the bridge has a `home`; when that copy is missing or the fetch fails, it warns and fetches from the repo's first remote instead. A repo already checked out is left as it is. Its usage takes a repo, so pass refuses any other doc. The work is [hydrate-repo](01a15baf-13e2-7bd8-8dc8-80d4871f2210.md)'s, which other capes import.
