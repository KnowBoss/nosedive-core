# Cape manifest

Each entry has the cape's `id`, its `owner`, the seeded id of the repo it was built from, and `shortName`, its cape root doc's name, its `repo` id, the `ref` config asked for (empty for trunk), the `commit` it resolved to, the `core` id it was built against and that core's `coreVersion`, the top-level user `actions` it provides (name to gist), the `kinds` it declares (name to declaration with its `version` and schema `digest`, as a built cape exports them), the seeded ids of the capes it `supersedes`, when its root links any (see build-cape), the ids of the capes it imports as `needs` (by repo name), its `version` and `builtAt`. It is how a run finds the cape for an unpinned ref without the network, how `help` lists capes' actions and crud checks docs against capes' kinds without loading them, and how seed names the core a failing cape last built with.
