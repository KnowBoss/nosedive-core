# Cape manifest

Each entry has the cape's `id`, its `repo` id, the `ref` config asked for (empty for trunk), the `commit` it resolved to, the `core` id it was built against and that core's `coreVersion`, the top-level user `actions` it provides (name to gist), the ids of the capes it imports as `needs` (by repo name), its `version` and `builtAt`. It is how a run finds the cape for an unpinned ref without the network, how `help` lists capes' actions without loading them, and how seed names the core a failing cape last built with.
