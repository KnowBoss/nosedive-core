# Cape

`cape` lists each cape config `capes` names, with the actions its build provides, or that it is not built.

`cape <remote>` adds a cape: it clones the remote, refuses it unless its root is a `cape`, and takes the cape's name from that root. It registers a repo doc by that name, with the remote as `meta.remotes.cloud`; a repo doc of that name with another remote is refused. It builds the cape against the running core at `--ref`, or the trunk, and only then lists it in config `capes` and commits; actions it shares with core or another cape are the launcher's to resolve. It prints the actions the cape brings.

`cape --drop <name>` takes the cape out of `capes` and commits. Its repo doc and builds stay: the doc may name a repo for other reasons, and builds are only cache.

Seed is what keeps capes built: after the core changes, it builds each again. `cape` builds once, when adding.
