# Describe cape source

Reads the repo's kb, the one its config names, else `kb/`, for its actions, functions and migrations, each with its usages and entrypoint, a migration's code read as a function's, and its kinds, each with its meta and links, from `.nosedive/kinds/` as well as the kb. A doc counts only when its kind, by doc-kind, is core's `action`, `function`, `migration` or `kind`: a cape's action docs say so in a canonical scope naming core, and a doc of a kind of the repo's own that is named `action` is another. It learns each doc's kind name from the head of its file with kb-doc-kind, and reads whole only the docs of those names; every doc in `.nosedive/kinds/` is a kind. Asked for another directory, as scaffold-cape is for a doc in one of the repo's other roots, it reads that in place of the kb. Asked to read from `src/`, as a hero's build and help are, it reads only the docs whose ids name a file there. Each kind is recorded with its `id`, its `file` in the repo, its `dropWhen` when its doc has a `## Drop when` section, or a legacy `## Done when`, its heading read in any case (that section's whole text, trimmed, empty when the section is, see kind; `dropWhenSlips` names a heading that looks like one but is not read as one, and an empty section) and, when asked for versions, its `version`: the newest commit that changed `meta.schema`, never one that changed its prose (see find-kind). The build asks, and the manifest and the bundle carry it, so a hero that wears a cape can name a kind's version in its docs without the cape's history; a kind whose schema is not committed has none. It records with the version whether it is on the repo's origin trunk, as last fetched, and with every kind, versioned or not, its `digest`: a short digest of the schema (`schemaDigest`, the first 12 hex characters of the sha256 of the schema with its keys in order), which scope entries keep as `schema` so a version a force-push orphaned can be re-pinned to a commit holding the same schema (see find-kind). `namedExports` lists, for each non-test file in `src/`, the values and types it exports besides its default `i<hex>` function, which core's build and load-source-cape hand to capes that import them. `uncanonicalDocs` counts the action, function and migration docs that do not name core as their kind's owner, which the build uses to refuse a cape written before canonical kinds, since those docs are otherwise left out without a word. Used by the build, the checks, scaf, and tests that run a cape from source.
