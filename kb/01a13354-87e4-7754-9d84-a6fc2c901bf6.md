# Describe cape source

Reads the repo's kb, the one its config names, else `kb/`, for its actions, functions and migrations, each with its usages and entrypoint, a migration's code read as a function's, and its kinds, each with its meta and links, from `.nosedive/kinds/` as well as the kb. A doc counts only when its kind, by doc-kind, is core's `action`, `function`, `migration` or `kind`: a cape's action docs say so in a canonical scope naming core, and a doc of a kind of the repo's own that is named `action` is another. It learns each doc's kind name from the head of its file with kb-doc-kind, and reads whole only the docs of those names; every doc in `.nosedive/kinds/` is a kind. Asked to read from `src/`, as a hero's build and help are, it reads only the docs whose ids name a file there. Each kind is recorded with its `id`, its `file` in the repo and, when asked for versions, its `version`: the newest commit that changed `meta.schema`, never one that changed its prose (see find-kind). The build asks, and the manifest and the bundle carry it, so a hero that wears a cape can name a kind's version in its docs without the cape's history; a kind whose schema is not committed has none. It records with the version whether it is on the repo's origin trunk, as last fetched. Used by the build, the checks, scaf, and tests that run a cape from source.
