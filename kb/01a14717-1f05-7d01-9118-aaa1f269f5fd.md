# Find kind

The hero's own kinds come first: a `kind: kind` doc of that name in each kb directory given, in order, then, given a hero repo, among the kinds it keeps in `.nosedive/kinds/`. Then the worn capes': the loaded capes' `kinds` besides core's, and, given a hero repo, the kinds its configured capes' builds recorded, so a core action like crud knows a cape's kinds without loading the cape; two capes declaring it is refused, naming each `<cape>:<kind>`. Then core's. `<cape>:<kind>` looks only in that cape, core's by its name and the hero's own by its root's name, and refuses a kind it does not declare.

It returns the declaration's meta: its `schema`, and `durable` when it says so, with the declaration's `links`, which name the gates its docs pass through, and `from`, whose it is: `hero`, or the cape's name. Nothing declares the kind when it returns nothing. Check-meta validates against the schema; crud's `--drop` reads `durable`; crud's mint sends core's `kind` and `repo` to `.nosedive/`.

## Canonical-kinds

Bare names resolve only in the acting seeded repo. Qualified short root name, long repo name or owner seeded id resolves only an unambiguous owner. Kind metadata includes owner, name and schema version, the last commit changing meta.schema. Catalog uses these same identities and spellings.
