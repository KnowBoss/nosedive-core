# Dehydrate repo

It takes the hero, the repo's doc and `{ discard }`, and pushes nothing: it refuses, keeping the checkout, while the checkout holds anything origin does not have, so that removing it loses nothing.

- Uncommitted changes or untracked files: refused, listing them.
- Commits origin lacks, on a branch or detached: refused, naming them. Origin has a commit when one of its branches or `refs/nosedive/*` refs, as last fetched, holds it; a cape that keeps work under its own refs pushes it there first.
- Ignored files (a `.env`, build output): refused with an error named `DehydrateIgnored` whose `ignored` lists them, unless `discard` is set, which removes them. A cape can catch it, keep what it wants of them, and dehydrate again with `discard`.

Then the worktree is removed, by a git command that names the user's cache with `--git-dir` (hydrate's `cacheGit`), so it works under `safe.bareRepository=explicit`; the cache keeps any branch it was on. A repo with no checkout is said to have none.
