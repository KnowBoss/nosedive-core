# Cape

A repo is a cape when it holds `.nosedive/cape.md`, a doc of this kind named for it, or, before kind files, when the root its config names is of this kind: `nosedive seed --root-kind cape` makes one. The root's name, which seed takes from the repo folder, is the cape's name: `nosedive cape <remote>` registers the repo by it. Only a cape is added by `cape` or built by seed, and scaf scaffolds only a cape or a ship; any other repo is refused, so config cannot list a repo that merely has a kb as a cape.

The kind links core's cape-tests-pass as `test.gate`, so `nosedive pass --test <root>` runs any cape's tests.

The schema is closed and declares nothing yet. What is true of a cape as a whole, rather than of one action, belongs here: in time, whether it is paid, the crew it is built for, the cores it supports.

## Core

Core is the cape every bridge has, and it holds only what is truly required to set up, build and run capes: the launcher, the actions a bridge needs to seed itself and manage its capes and kb, the kinds they rely on, and the lib every cape imports. So any free user, with core alone, can build whatever they want from their bridge. Anything else is built as a cape, from the capes there are, and comes into core only when building capes cannot work without it.
