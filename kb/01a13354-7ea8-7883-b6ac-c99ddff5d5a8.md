# Seed

On a repo with no `.nosedive/config.yaml`, seed mints the repo's id, writes the config (`self`, `kb: ./kb`, `root`), mints the root doc that `root` names, a memo or the kind `--root-kind` gives (`cape` for a cape repo, `base` for one a team works from), ignores `capes/` and `local/` in `.nosedive/.gitignore`, leaving the repo's own `.gitignore` alone, and commits. A base's root also gets `meta.workspace: ./workspace`, and seed makes that folder with a `.gitignore` of `*` inside it; if the path has changed since the last seed, it moves the folder there. On a bridge, it adds whatever of that is missing and leaves everything else alone; a config naming its id as `bridge`, or its root as `backlog`, the older names, has them.

Then it builds every cape the config's `actions` name and the bridge does not have yet, against the core that is running: a pinned commit once, an unpinned ref at whatever its remote has now. `--no-capes` skips that. A run of an action whose cape is missing says to run `seed`. Config cannot name a cape for an action core has: seed refuses it, naming the entries to remove.

```yaml
actions:
  hello: nosedive-hello          # its trunk, as of the last seed
  greet: nosedive-hello@<commit> # pinned
```
