# Seed

On a repo with no `.nosedive/config.yaml`, seed mints the bridge's id, writes the config (`bridge`, `kb: ./kb`), creates the kb, ignores `.nosedive/capes/`, and commits. On a bridge, it adds whatever of that is missing and leaves everything else alone.

Then it builds every cape the config's `actions` name and the bridge does not have yet, against the core that is running: a pinned commit once, an unpinned ref at whatever its remote has now. `--no-capes` skips that. A run of an action whose cape is missing says to run `seed`.

```yaml
actions:
  hello: nosedive-hello          # its trunk, as of the last seed
  greet: nosedive-hello@<commit> # pinned
```
