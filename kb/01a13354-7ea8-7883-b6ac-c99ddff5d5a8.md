# Seed

On a repo with no `.nosedive/config.yaml`, seed writes the config (the root, and `kb`: `./bridge` for a ship, its bridge, `./kb` for any other repo) and mints the root doc it names, a `ship` unless `--root-kind` gives another kind (`cape` for a cape repo, `base` for a repo of data, `memo` for a repo that is only nosedive-aware). The config names the root under its kind's key, `ship`, `cape` or `base`, and as `root` for any other kind; ignores `cache/`, `capes/` and `local/` in `.nosedive/.gitignore`, leaving the repo's own `.gitignore` alone but for one line in a cape's or a base's, `!package-lock.json`: their packages build from the lockfile, which a user's global ignore could otherwise hide from every commit; and commits. A ship's root also gets `meta.workspace: ./workspace`, and seed makes that folder with a `.gitignore` of `*` inside it; if the path has changed since the last seed, it moves the folder there. On a bridge, it adds whatever of that is missing and leaves everything else alone; a config naming its root under any of those keys, or as `backlog`, the oldest, has its root.

The root's body is its tree, which seed renders on every run and commits when it changed (`seed: <repo> tree rendered`): its title, then a `## ` section for each rel group of its `<group>.feat` links, and under each doc the docs it links as `child.feat`, to any depth, whatever their kinds. `--no-capes` does not skip it.

Then it builds every cape config `capes` lists that the bridge has not built for the core that is running: a pinned commit once, an unpinned ref at whatever its remote has now. `--no-capes` skips that. A new core means a new build of each cape; that is seed's job, and `nosedive cape` only builds the one it adds. Seed builds every cape it can before failing on those it could not, naming each and why, and, when the manifest says which core last built one, how to get back to it: pin the cape at that commit, or run that core. It never goes back on its own. Capes may declare actions core or other capes declare: the launcher resolves shared names (see launch).

```yaml
capes:
  - nosedive-example-cape            # its trunk, as of the last seed
  - nosedive-other-cape@<commit>     # pinned
```
