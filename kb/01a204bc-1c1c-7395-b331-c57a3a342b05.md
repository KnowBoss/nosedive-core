# Legacy hero guard

A hero for September's nosedive (2026.9.18) is one whose config names a `backlog` and lists no `roots`, the test legacy-capes uses, or one still on the older `.nosediverc` config (see below). This core does not run on one: launch calls this before it looks up an action, so every command line, help and `seed` included, is refused with exit 1 before anything is read for writing. Only `pre-push.hook`, which launch handles first, still exits 0 in silence.

The refusal says the hero is for September nosedive and that nothing was changed, and names the hero's root. 2026.9.18 acts on the directory it is run in, so a line for it is only safe anchored to the root:

- **At the root** it prints bash `cd '<root>' && npx -y nosedive@2026.9.18 <args>`, the root always single-quoted, a plain one too, and each argument bare when plain and single-quoted otherwise. It adds PowerShell `Set-Location -LiteralPath '<root>'; npx -y nosedive@2026.9.18 <args>` only when every argument is in the set the real npx.ps1 passes unchanged under Windows PowerShell 5.1 and pwsh: a word, a `--option`, `.`, `..` or a relative path of them, or a hyphenated hex id such as a uuid; never an empty argument, a quote, a bare `--`, a single hyphen, a number, or anything PowerShell reads for itself (`, @ $ ; & | ~ { ( < #`, a backtick, a space). Otherwise it prints the bash line alone and says that no PowerShell line is given because an argument would not pass through npx.ps1 unchanged. Bash arguments are quoted, so the bash line carries any.
- **On Windows, an argument npx's cmd.exe launch would cut** gets no line in either shell (decision legacy-line-windows-newline, @see kb/01a20622-90a9-733d-9bcb-aca009dc4338.md). npm starts a package's bin through cmd.exe there, whatever shell the line is pasted in; it ends the command line at a newline and drops a carriage return, and passes every other character from U+0001 to U+007F, and the non-ASCII ones tried, unchanged (observed with npm 11.19.0). So when any argument holds `\n` or `\r` the refusal, at the root, prints no npx line: it names the root, says the command line cannot be given on Windows, and names the first such argument, as JSON so its line break shows. Elsewhere the lines print as above, and away from the root nothing changes. The function takes the platform as an optional last parameter, defaulting to the one it runs on, so both branches are tested on every OS.
- **Anywhere else** (a subdirectory, the workspace, a kept checkout, `NOSEDIVE_HERO` named from outside the root) it prints no npx line: it names the root and says to run the same command again from there.

It names no newer version and offers no flag past it.

- **Whose hero**: the one launch acts through, the nearest config above where nosedive acts, `NOSEDIVE_HERO` setting that directory. `--at` does not choose it: launch reads the hero from where it runs whatever `--at` names, so a modern hero is never refused for a September one in its workspace, a September hero is refused though `--at` names a modern one, and outside any hero `--at` fails as it always did.
- **Checkouts**: a kept checkout in a September hero's workspace gets this refusal, not launch's "a checkout is never a hero": 2026.9.18 ran there and has no `--at`. Launch passes the checkout's hero to the guard, which judges that hero's config; a checkout in a hero that is no September one keeps launch's refusal.
- **A `.nosediverc` bridge**: a bridge made by `init` in nosedive 2026.7.24 or earlier is a `.nosediverc` file, which 2026.9.18 still reads and `seed` converts (fixes defect september-nosediverc-bridge-unguarded, @see kb/01a205fc-99f3-72dd-9d39-b37e80ff1ada.md). The guard finds it as 2026.9.18 does, walking up from where nosedive acts, per directory: a `.nosedive/config.yaml` is judged as above and ends the walk; else a `.nosediverc` that is a regular file makes that directory a September root, whatever it holds (it is never parsed); a directory with both is judged by its config.yaml alone. It is refused by the same rules and message as any September hero, and `seed` too, since core's own `seed` there would write a config.yaml beside it, which 2026.9.18 then refuses as ambiguous. A `.nosediverc` that is a directory or missing is no bridge. A kept checkout under such a bridge is refused with the bridge's root because the walk reaches it; launch's `insideWorkspace` reads only config.yaml, so a checkout that holds a config.yaml of its own, in a `.nosediverc` bridge's workspace, is judged as the hero it holds, not refused for the bridge (not settled; `.nosediverc` is not parsed, so its workspace is not known).
- **Never a match**: a config with `roots`, which includes a hero part-way through a migration; a `backlog` that is not a string; a config that is empty, not a mapping, or cannot be read; and one that is not a regular file, which is never opened. A config is read whatever its size (decision legacy-config-oversized, @see kb/01a20631-d3aa-790f-8fa8-88d8aea020ee.md), as core's own config reader does right after, so a September config over 1 MiB is refused like any other. A broken config is never turned into a refusal here, only into whatever it would have caused.

The September tag is the one fact this holds; move it only with the pilot's say.

Further tests make a `.nosediverc` bridge with the published 2026.7.24 `init --headless` from npm (2026.9.18 never writes one), run every command class on it as for the config.yaml hero above, and run a printed read-only line (`list-dives`) with the real 2026.9.18 from outside, which acts on that bridge (compatibility level 0); a precedence test covers `.nosediverc` contents, a config.yaml beside it, the nearest directory and a `.nosediverc` that is no regular file, with no npm. They need npm like the rest: under `CI` a missing npm fails.

The tests make a hero with the published 2026.9.18 from npm, jumped, with a kept checkout and a dive in progress, and again made afresh with its remotes gone (a copy would keep its checkout wired to the first hero), assert that the offline checkout points into nothing of the online one, run every command class on it, in process and as the built CLI, in the root, the workspace, the checkout and a subdirectory, and assert that no file, mode, modified time, ref, config or remote changed. One runs a printed read-only line (`list-dives`) with the real 2026.9.18 from a directory outside the hero and compares what it prints with a run in the hero. Another pastes each printed line into bash, Windows PowerShell and pwsh, through the real npx (npx.ps1 on Windows, which the test checks), with a stub package standing in for nosedive@2026.9.18 installed offline in the hero, so no registry is needed and the real npx still resolves and starts it; the package prints the arguments it got, which must be those typed; on Windows an argument with a line break has no line to paste, and the test asserts the refusal for it. A root a POSIX shell would take bare is tested quoted all the same (it cannot be made on Windows, where the test is skipped). They need npm and the shells: where absent they are skipped, unless `CI` is set, when a missing one fails. CI builds before it tests.
