# Legacy hero guard

A hero for September's nosedive (2026.9.18) is one whose config names a `backlog` and lists no `roots`, the test legacy-capes uses. This core does not run on one: launch calls this before it looks up an action, so every command line, help and `seed` included, is refused with exit 1 before anything is read for writing. Only `pre-push.hook`, which launch handles first, still exits 0 in silence.

The refusal says the hero is for September nosedive and that nothing was changed, then prints `npx -y nosedive@2026.9.18` followed by the same arguments. When every argument is plain that is one line; otherwise each argument is quoted for bash and zsh and, in a second line, for PowerShell, since no one quoting reads alike in both. It names no newer version and offers no flag past it.

- **Whose hero**: the one launch acts through, the nearest config above where nosedive acts, `NOSEDIVE_HERO` setting that directory. `--at` does not choose it: launch reads the hero from where it runs whatever `--at` names, so a modern hero is never refused for a September one in its workspace, a September hero is refused though `--at` names a modern one, and outside any hero `--at` fails as it always did.
- **Checkouts**: it runs after launch's refusal to act inside a workspace checkout, which stands: from a checkout in a September hero's workspace nobody is told to run the old nosedive.
- **Never a match**: a config with `roots`, which includes a hero part-way through a migration; a `backlog` that is not a string; a config that is empty, not a mapping, or cannot be read; and one that is not a regular file or is over 1 MiB, which is never opened. A broken config is never turned into a refusal here, only into whatever it would have caused.

The September tag is the one fact this holds; move it only with the pilot's say.

The test makes a hero with the published 2026.9.18 from npm, jumped, with a kept checkout and a dive in progress, and again with its remotes gone, runs every command class on it, in process and as the built CLI, and asserts that no file, mode, modified time, ref, config or remote changed. Another pastes each printed line into bash and PowerShell and compares the arguments a stub for npx receives. They need npm and the shells: where absent they are skipped, unless `CI` is set. CI builds before it tests.
