# Legacy hero guard

A hero for September's nosedive (2026.9.18) is one whose config names a `backlog` and lists no `roots`, the test legacy-capes uses. This core does not run on one: launch calls this before it looks up an action, so every command line, help and `seed` included, is refused with exit 1 before anything is read for writing. Only `pre-push.hook`, which launch handles first, still exits 0 in silence.

The refusal says the hero is for September nosedive and that nothing was changed, then prints `npx -y nosedive@2026.9.18` followed by the same arguments, each quoted to be pasted. It names no newer version and offers no flag past it.

- **Whose hero**: the nearest config above where nosedive acts, so a subdirectory, the workspace, or a checkout in it, and `NOSEDIVE_HERO`, which sets that directory, all find the hero holding them. With `--at <target>` it is the nearest config above the target, a root's name or a directory not made yet counting as a path under the hero it is run in.
- **Never a match**: a config with `roots`, which includes a hero part-way through a migration; a `backlog` that is not a string; a config that is empty, not a mapping, or cannot be read. Those run as before, so a broken config is never turned into a refusal here, only into whatever it would have caused.

The September tag is the one fact this holds; move it only with the pilot's say.
