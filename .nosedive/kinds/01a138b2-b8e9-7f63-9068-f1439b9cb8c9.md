# Kind

A `kind: kind` doc declares a kind: its `name` is the kind's name, and crud checks the `meta` of every doc of that kind against its `meta.schema` when it mints one or changes its meta. The schema must say whether it is closed: `additionalProperties: false` makes an undeclared key an error rather than a silent typo.

A kind is durable when its doc does not say how a doc of it is dropped: docs of a durable kind are things kept and maintained, not steps on the way to them, and `crud --drop` refuses one unless given `--hard`, since its file is what keeps it findable by id. Core declares only the kinds it needs, all durable; kinds for passing work, such as goals or dives, belong to the bridge that uses them.

A durable doc hangs only off a root or another durable doc: crud refuses a new `.feat` link that would hang one under a doc that is neither, and a new `.spec` link from a doc that is not durable, since specs shape what lasts and are linked from it, work linking to what it needs (specs-on-durable; see edit-kb-docs). So the docs a hero's roots reach are a durable trunk, the things kept, with non-durable fringes, the work on the way to them, and dropping a fringe never orphans anything kept.

A kind that is not durable says how a doc of it is dropped, in a `## Drop when` section of its doc (drop-when): that section is what makes it droppable, and there is no flag to set beside it. It is written for the agent about to drop one: what must be true first and what must be recorded where, for work is done when it is dropped. `crud --drop` quotes it when it refuses a doc of the kind (see crud), and a build records the whole section as `dropWhen`, empty when the section is; `next` never prints it, since what done looks like matters only once a doc is picked. A kind doc still headed `## Done when`, as before drop-when, is read the same until the drop-when migration renames it. An edit that adds or removes the section changes the kind's durability, and crud says so; it warns too of a heading that looks like one but is not read as one, such as `### Drop when`, and of an empty section. `meta.next` names rels, other than those ending `.feat`, by which a walked doc linking a doc of this kind makes `next` list it, as a question kind names `open.spec` so a feat's unanswered questions are listed under it.

A kind comes from the kb being written first, then the bridge's, then the loaded capes, core first, so a bridge that declares a kind of its own name overrides a cape's, durability included. A doc whose kind nothing declares, such as one from before kinds were canonical, has its meta written with a warning, unchecked, and is not durable; a new one cannot be written (see crud).
