# Repo

`remotes` maps a role to a URL or a path, a path being relative to the bridge. Core knows one role, `origin`, which every repo has: where its checkouts fetch from and push their work to, GitHub or, for a repo that must stay private, a bare repo on a host its owner controls. Any other role is a cape's to give meaning, such as a backup. A repo doc carries no path: [hydrate-repo](../../kb/01a15baf-13e2-7bd8-8dc8-80d4871f2210.md) checks a repo out at `<workspace>/<name>`, the workspace being the hero's, and [dehydrate-repo](../../kb/01a17fba-20d6-73c5-b8dd-8551943369a2.md) puts it away.

Any git repo can be registered with an origin, whether or not nosedive manages it. What a registered repo is, a cape, a hero repo or data, its own config says whenever it is read. A registered cape is attached to the target root with `pass --attach-cape <repo>` and detached with `pass --detach-cape <repo>`, gates this kind links.
